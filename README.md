# Campus

Минимальный интерфейс для Hochschule Flensburg Stud.IP в Catppuccin Mocha: форма входа, карточки курсов и просмотр файлов.

## Запуск

Нужен Node.js 22.12 или новее.

```sh
npm install
make dev
```

Открой http://localhost:5173 и войди с обычными логином и паролем Stud.IP. Кнопка «Посмотреть демо» открывает пример ленты без входа.

В режиме разработки сервер доступен и с других устройств в локальной сети: открой `http://<IP компьютера>:5173`, например http://192.168.178.22:5173. Чтобы ограничить доступ текущим компьютером, запусти `HOST=127.0.0.1 npm run dev`. Адрес и порт можно задать через `HOST` и `PORT` в `.env`.

Для готовой сборки:

```sh
npm run build
npm start
```

## Авторизация

Campus получает штатную форму входа Stud.IP, сохраняет её CSRF-токен и login ticket, затем отправляет логин и пароль по HTTPS на ту же форму. Успешный вход подтверждается запросом `/jsonapi.php/v1/users/me`. Пароль используется только в ходе входа и не записывается на диск, в сессию или localStorage.

Браузер получает собственную подписанную cookie Campus с `HttpOnly` и `SameSite=Strict`; при HTTPS добавляется `Secure`. Сессии разных браузеров независимы. При каждом успешном входе идентификатор сессии меняется. Сессия Campus действует максимум семь дней; если Stud.IP завершит свою сессию раньше, приложение предложит войти заново. Автоматический опрос не продлевает этот срок.

Сессии Stud.IP хранятся на сервере в `.data/sessions.enc`, зашифрованном AES-256-GCM. Ключ `.data/session.key` создаётся автоматически. Каталог имеет права `0700`, файлы сессий и ключа — `0600`. Эти файлы исключены из Git. Сессия сохраняется после перезапуска сервера. При выходе она удаляется, и прежняя cookie больше не даёт доступа к приватным API.

Запросы на изменение состояния принимают JSON и проверяют источник. Вход ограничен десятью неудачными попытками за пятнадцать минут с одного IP. Ошибка загрузки материалов после входа не отменяет успешную авторизацию.

В режиме разработки сервер слушает `0.0.0.0`, а при `npm start` — `127.0.0.1`. Переменная `HOST` переопределяет адрес в обоих режимах. Это приложение для одного процесса Node.js. Публичное развёртывание и конфигурация HTTPS-прокси не входят в текущую настройку.

## Курсы и файлы

Главная страница показывает карточки всех курсов с количеством доступных файлов и непрочитанных изменений файлов. Карточки можно перетаскивать мышью, а на сенсорном экране — за ручку в правом верхнем углу. На ручке также работают стрелки клавиатуры. Порядок сохраняется в браузере; новые курсы добавляются в конец.

Нажатие на курс открывает его файлы в сетке плиток с миниатюрами первой страницы PDF и изображений, именами и датами. Название курса находится рядом со ссылкой «Все курсы». Новые и изменённые файлы отмечены зелёной обводкой без текстовых лейблов. Фильтров и отдельной вкладки обновлений нет. Файлы идут от самых новых к самым старым по дате изменения, а при её отсутствии — по дате создания. Файлы без даты находятся в конце. Ссылка «Все курсы» возвращает на главную; кнопки «Назад» и «Вперёд» браузера тоже работают. Ссылку на выбранный курс можно скопировать из адресной строки.

После первого входа сервер сохраняет исходное состояние курсов текущего семестра. Уже существующие материалы не выдаются за новые. Затем он проверяет файлы, объявления, расписание и основные сведения курсов раз в пять минут. Браузер получает данные раз в тридцать секунд. Если проверка не удалась и список пуст, доступна кнопка повторной проверки.

Нажатие на файл открывает просмотр в новой вкладке браузера через сохранённую серверную сессию Stud.IP. PDF, изображения, аудио, видео и текстовые файлы передаются для просмотра; HTML и SVG показываются как текст. Если браузер не поддерживает формат, открывается страница с кнопкой скачивания без автоматической загрузки файла. Файл передаётся потоком и не сохраняется на сервере Campus. Завершённая полная передача помечает связанные уведомления прочитанными; история остаётся доступной через API. Снимки и история хранятся в `.data/state.json` отдельно для каждого аккаунта; сохраняются последние 2000 изменений.

Сведения о недоступных файлах показаны в карточке курса и внутри него.

Если Stud.IP запрещает чтение отдельного раздела курса с ответом 403, остальные разделы продолжают отслеживаться. Интерфейс сообщает об ограниченном доступе. Последние данные недоступного раздела сохраняются и не считаются удалёнными. После восстановления доступа раздел получает новую исходную точку сравнения, чтобы изменения за период без доступа не выдавались за новые. Ошибки связи, истечение сессии и другие ошибки отменяют обновление снимка целиком.

Изменения между двумя опросами, которые успели исчезнуть до следующего, обнаружить нельзя. Исчезновение объекта из доступного списка может означать удаление или изменение прав доступа. Форум, wiki и Courseware пока не подключены.

## Чтение данных

Единственный POST к университету — отправка его формы входа. Все запросы к данным используют GET. Campus не редактирует материалы или настройки Stud.IP. Для видимых плиток PDF и изображений браузер загружает данные миниатюр. Для PDF отображается первая страница; миниатюры хранятся только в памяти браузера и очищаются при смене аккаунта. Их загрузка не помечает файлы прочитанными. Полный просмотр открывается по нажатию. Для этого используется [штатный адрес sendfile.php](https://hilfe.studip.de/admin/Admins/Installationsanleitung). Ссылки пагинации и перенаправления при входе проверяются: учётные данные и cookie не отправляются на другие сайты.

Маршруты данных:

```text
GET /jsonapi.php/v1/users/me
GET /jsonapi.php/v1/semesters
GET /jsonapi.php/v1/users/{id}/courses?filter[semester]={id}
GET /jsonapi.php/v1/courses/{id}/file-refs
GET /jsonapi.php/v1/courses/{id}/news
GET /jsonapi.php/v1/courses/{id}/events
```

Локальный API:

```text
POST /api/auth/login          { "username": "...", "password": "..." }
POST /api/auth/logout         {}
GET  /api/state
GET  /api/demo
GET  /api/changes?since=2026-10-02T12:00:00Z
GET  /api/files/{fileRefId}/download
GET  /api/files/{fileRefId}/preview
GET  /api/files/{fileRefId}/content
POST /api/sync                {}
POST /api/changes/read        { "id": "..." }
```

Приватные маршруты требуют действующую cookie Campus. Скачать можно только файл из снимка текущего аккаунта; Stud.IP повторно проверяет права при скачивании. Cookies университета остаются на сервере. Перенаправления скачивания на внешние адреса не поддерживаются. `/api/state` без входа сообщает только статус авторизации; `/api/demo` содержит только демонстрационные данные. Ручная вставка университетской cookie и `STUDIP_COOKIE` больше не используются.

Форма входа сверена с текущей установкой Hochschule Flensburg. Схемы и маршруты сверены с [исходным кодом Stud.IP](https://gitlab.studip.de/studip/studip/-/blob/main/lib/classes/JsonApi/RouteMap.php). Автоматические проверки используют тестовый сервер университета; успешный вход в реальный аккаунт требует твоих данных в интерфейсе.

## Проверки

```sh
npm test
npm run build
```

Тесты проверяют вход через форму с CSRF, перенаправления и cookies, ошибки пароля, изоляцию аккаунтов, ротацию идентификатора сессии, восстановление после перезапуска, выход, истечение срока, шифрование, ограничение попыток входа и обнаружение изменений. Для скачивания проверяются права аккаунтов, передача бинарных данных, диапазоны, отмена передачи и отметки прочитанного.

Палитра: [Catppuccin](https://catppuccin.com/palette/). Иконки: Lucide. Шрифт: Manrope с системным запасным шрифтом.
